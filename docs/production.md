# 生产部署指南

本文档描述 vehix-agent 从 Demo 到生产级需要补齐的层次。

## 架构分层

```
┌─ 接入层 ────────────────────────────────────────┐
│ MQTT (EMQX)           │ 车辆上报入口 (10万+ msg/s) │
│ API Gateway (Kong)    │ 限流 / 鉴权 / 路由        │
├─ 应用层 ────────────────────────────────────────┤
│ FastAPI × N           │ 多副本 + HPA 自动扩缩     │
│ LangGraph Agent       │ LLM 调用池 + 限流        │
│ Redis                 │ 会话 / 缓存 / 审批队列   │
├─ 数据层 ────────────────────────────────────────┤
│ PostgreSQL            │ 主从复制 + 读写分离       │
│ S3/MinIO              │ OTA 固件包存储           │
│ Elasticsearch         │ 遥测数据全文检索          │
├─ 可观测性 ──────────────────────────────────────┤
│ Prometheus + Grafana  │ 指标监控                  │
│ ELK / Loki            │ 日志聚合                  │
│ OpenTelemetry         │ 全链路追踪                │
└─────────────────────────────────────────────────┘
```

## 各层要求

### 接入层

| 维度 | Demo | 生产 |
|------|------|------|
| 协议网关 | Python 模拟器 | EMQX + 协议适配器 |
| 连接加密 | HTTP 明文 | mTLS（车端证书双向认证） |
| 设备管理 | 无 | T-Box 注册/激活/吊销全生命周期 |
| 断线重连 | 无 | 离线数据补传 + 断点续传 |

### 应用层

| 维度 | Demo | 生产 |
|------|------|------|
| 部署 | 单进程 | K8s Deployment × 3 + HPA |
| 会话管理 | MemorySaver | Redis |
| 审批队列 | 内存 asyncio.Queue | Redis Pub/Sub |
| LLM 调用 | 单次同步 | 调用池 + 优先级队列 + 限流 |
| 熔断降级 | 无 | LLM 不可用 → 规则引擎 |

### 数据层

| 维度 | Demo | 生产 |
|------|------|------|
| 数据库 | SQLite 单文件 | PostgreSQL 主从 + 自动备份 |
| 数据保留 | 无限增长 | 原始数据 30 天 TTL，聚合数据 3 年 |
| 数据迁移 | 删库重建 | Alembic + 灰度执行 + 回滚 |
| 多租户 | 全局单库 | tenant_id 隔离 + 行级安全 |

### 可观测性

| 维度 | Demo | 生产 |
|------|------|------|
| 日志 | JSON stdout | ELK/Loki 集中存储，保留 90 天 |
| 监控 | 无 | Prometheus（QPS/延迟/错误率/LLM 调用量） |
| 告警 | 无 | PagerDuty/飞书（服务宕机、错误率飙升） |
| 追踪 | 无 | OpenTelemetry（API → Agent → Tool → DB） |

### 安全

| 维度 | Demo | 生产 |
|------|------|------|
| 密钥管理 | `.env` 明文 | Vault / K8s Secret + 自动轮转 |
| 审批流 | 单人 | 多因子 + 操作录像 + 不可篡改审计链 |
| 数据脱敏 | 无 | 驾驶员姓名/VIN 掩码 |
| 合规 | 无 | 等保二级/三级 + GB/T 32960 平台过检 |
| 渗透测试 | 无 | OWASP Top 10 + 车联网专项 |

### 测试

| 维度 | Demo | 生产 |
|------|------|------|
| 单元测试 | 0% | > 80% 覆盖率 |
| 集成测试 | 无 | Agent 全链路 / MCP 工具链 |
| E2E | 无 | Playwright 前端自动化 |
| 性能 | 无 | k6/locust（1000 SSE 并发 / 10000 TPS 写入） |
| 混沌 | 无 | MQTT 断连 / DB 宕机 / LLM 超时 |

## 目标场景

### 新能源车企云端运维

**客户画像**：比亚迪、蔚来、小鹏、理想

当前痛点：故障诊断靠人工看 DTC 码 + 经验判断。vehix-agent 的差异化在于 Agent 驱动的自动诊断 + OTA 灰度管理 + MCP 工具标准化。

### 第三方车队管理

**客户画像**：G7、中交兴路、汇通天下

管理数十万到上百万台商用车辆，核心痛点：
- 多协议接入（不同车型不同终端，多系统切换）
- 故障响应时效（危化品车制动故障需分钟内响应）
- 合规成本（"两客一危"监管要求）

### 保险科技 (UBI)

**客户画像**：众安保险、平安产险

UBI 需要分析驾驶行为数据定价。vehix-agent 的遥测管道可扩展为：急加速/急减速检测、驾驶行为评分、事故前数据快照。

### 政府监管平台

**客户画像**：地方交通局、工信部

GB/T 32960.1-2025 要求三级监管架构。vehix-agent 可作为公共平台的参考实现：多企业数据汇聚、自动告警聚合、合规自动化检查。

### 充电运营商

**客户画像**：特来电、星星充电、特斯拉超充

充电桩 + 车辆联合诊断是当前空白。Agent 同时分析桩端和车端数据，做"充电故障根因定位"——是车的问题还是桩的问题。
